# API and Protocol Outline

## 1. Status

This document began as the Goal 1 contract outline and now distinguishes implemented routes from planned completion work. It is not a substitute for the generated OpenAPI document. Payload details may evolve only if they preserve the requirements and receive contract tests.

The implemented vertical slice covers human session/authentication/MFA, platform tenant administration, tenant members, invitation creation/listing/revocation/acceptance, devices and enrollment codes, device groups, certificates, licences including transfer, contents and approval, playlists and publication, direct and scheduled/group assignments, audit queries, device enrollment/heartbeat/rotation, desired-state manifests and authorized asset streaming. Generated-client compatibility and synchronization-event ingestion remain planned.

## 2. Surfaces and authentication

| Surface | Proposed base | Authentication | Anti-forgery |
|---|---|---|---|
| Human session/bootstrap | `https://app.<domain>/api/v1` | Secure server session cookie | Required for unsafe methods |
| Tenant administration | `https://app.<domain>/api/v1/tenants/{tenantId}` | Cookie + active tenant membership/policy | Required for unsafe methods |
| Platform administration | `https://app.<domain>/api/v1/platform` | Cookie + Platform Administrator + MFA | Required for unsafe methods |
| Device bootstrap | `https://devices.<domain>/device/v1/enrollment` | One-use enrollment capability over server-authenticated TLS | Not browser-cookie based |
| Enrolled device | `https://devices.<domain>/device/v1` | Valid mTLS certificate bound to active tenant/device | Not browser-cookie based |
| Local Pi player | `http://127.0.0.1:<dynamic-or-configured>/player/v1` | Loopback-only narrow local session/origin gate | Local design; no backend credential |

The reverse proxy must remove any untrusted client-certificate forwarding header and set trusted certificate information only after validating the TLS connection.

## 3. General conventions

- JSON uses UTF-8 and camelCase names.
- Resource identifiers are opaque UUID strings.
- Times are ISO 8601 UTC instants (for example `2026-08-15T12:30:00Z`).
- Licence intervals are `[validFromUtc, expiresAtUtc)`; the end is exclusive.
- Unsafe human requests include an anti-forgery header bound to the session.
- `X-Correlation-ID` may be supplied in a valid bounded format or generated by the server and is returned in responses.
- `Idempotency-Key` is required where documented for enrollment, publication, licence transfer/renewal, and other retry-sensitive commands.
- Paged administration collections return arrays and an `X-Next-Cursor` header when more rows exist. Pass that header unchanged as the next `cursor` query parameter, retaining the same filters and limit. The token currently encodes an offset in a stable ordering; concurrent insertions/deletions can shift pages, so a traversal is not a database snapshot. Some small supporting collections remain bounded/unpaged; consult the controller/OpenAPI signature.
- `ETag`/concurrency version or an explicit version field protects important administrative updates.
- APIs return `401` for absent/invalid authentication and `403` for authenticated denial; neither response exposes another tenant's resource details.
- `404` may intentionally conceal a cross-tenant or inaccessible identifier.
- Rate-limit responses use `429` with safe retry guidance.

### Session security additions (September 2026)

Content Managers, Tenant Administrators, and Platform Administrators must complete MFA. Successful MFA confirmation, verification, recovery, and step-up rotate the session credential while preserving its original absolute expiry. Clients must reload `GET /api/v1/session` after MFA to obtain fresh session and anti-forgery state.

- `GET /api/v1/auth/sessions` lists the caller's unexpired sessions with `id`, `createdAtUtc`, `lastSeenAtUtc`, `absoluteExpiresAtUtc`, and `isCurrent`.
- `POST /api/v1/auth/sessions/{id}/revoke` requires recent MFA and returns 204; inaccessible identifiers return 404.
- `POST /api/v1/auth/sign-out-all` requires recent MFA and invalidates all of the caller's sessions.

The device heartbeat can include `licenseVerificationKeys`: the current public signing key followed by up to three additional public keys. This list is transported over the authenticated device TLS channel. Agents validate P-256/ES256 key identities before persisting the current key.

## 4. Human identity endpoints

| Method and path | Purpose | Key controls |
|---|---|---|
| `GET /session` | Current user, memberships, selected tenant, CSRF bootstrap, MFA/session state | No credential/token disclosure |
| `POST /auth/sign-in` | Password authentication | Generic error, rate limit, lockout, session rotation |
| `POST /auth/mfa/totp` | Complete MFA challenge | Bound short-lived challenge, replay protection |
| `POST /auth/sign-out` | Revoke current session | CSRF |
| `POST /auth/sign-out-all` | Revoke all user sessions | CSRF + recent authentication |
| `POST /auth/forgot-password` | Initiate recovery | Generic response, rate limit |
| `POST /auth/reset-password` | Consume reset token and reset | One-use/expiry, revoke prior sessions |
| `POST /invitations/{token}/accept` | Accept invitation or link account | One-use, tenant/email/role binding |
| `POST /mfa/totp/enroll` | Begin administrator TOTP enrollment | Reauthentication, secret shown only during enrollment |
| `POST /mfa/totp/confirm` | Confirm TOTP and issue recovery codes once | Reauthentication, audit |
| `POST /mfa/recovery/regenerate` | Replace recovery codes | MFA/recent authentication, revoke prior codes |

Public registration endpoints do not exist.

| Method and path | Purpose |
|---|---|

### Devices and groups

| Method and path | Purpose |
|---|---|
| `GET /tenants/{tenantId}/devices` | Filtered/paged devices and effective status |
| `GET /tenants/{tenantId}/devices/{deviceId}` | Inventory, licence, desired/applied state and recent health |
| `PATCH /tenants/{tenantId}/devices/{deviceId}` | Rename or allowed configuration changes |

| `PUT /tenants/{tenantId}/device-groups/{groupId}/members` | Atomically replace/patch same-tenant membership |

The raw enrollment code is returned once in the create response and never appears in list/audit/log responses.

Retry-sensitive mutations require an idempotency key and return a conflict for a key reused with a different body.

### Content, playlists, and assignments

| Method and path | Purpose |
|---|---|
| `GET /tenants/{tenantId}/contents` | List authorized content metadata |
| `POST /tenants/{tenantId}/contents` | Stream upload into quarantine and scan |
| `GET /tenants/{tenantId}/contents/{contentId}` | Content/version/scan metadata |
| `POST /tenants/{tenantId}/contents/{contentId}/versions/{versionId}/approve` | Explicitly approve a clean version |
| `POST /tenants/{tenantId}/contents/{contentId}/archive` | Archive if dependencies allow |
| `GET/POST /tenants/{tenantId}/playlists` | List/create logical playlists |
| `GET/PATCH /tenants/{tenantId}/playlists/{playlistId}` | Read/edit through a draft version |

## 7. Device bootstrap and protocol endpoints

| Method and path | Authentication | Purpose |
|---|---|---|
| `POST /device/v1/enrollment` | One-use code + validated server TLS | Submit CSR/inventory and atomically obtain certificate/configuration |
| `POST /device/v1/heartbeats` | mTLS | Report state; receive server time, authorization and desired-state summary |
| `POST /device/v1/certificates/rotate` | Current mTLS + proof of new key | Rotate before expiry |
| `GET /device/v1/desired-states/{desiredStateId}/manifest` | mTLS + device assignment | Obtain immutable authorized manifest |
| `GET /device/v1/desired-states/{desiredStateId}/assets/{contentVersionId}` | mTLS + current desired-state authorization | Stream one assigned object with byte-range support; the agent resumes a validated partial object and activates it only after exact length and SHA-256 verification |
| `POST /device/v1/synchronization-events` | mTLS | Report bounded sync/apply failure or completion events |

The device certificate authenticates the caller first; a body `deviceId` never substitutes for the authenticated certificate binding.

### Conceptual heartbeat response

```json
{
  "serverUtc": "2026-08-15T12:30:01Z",
    "heartbeatAfterSeconds": 30,
  "deviceState": "active",
  "authorization": {
    "status": "licensed",
    "signedLease": "compact-signed-value"
  },
  "desiredState": {
    "version": 8,
    "manifestSha256": "hex-digest",
    "changed": true
  }
}
```

The actual signed format/algorithm is selected by ADR and test vectors. Protocol documentation will include canonical serialization, allowed algorithms (no attacker-controlled downgrade), audiences, maximum clock skew, key rotation, and failure codes.

A valid lease with no effective assignment returns a distinct `licensedNoContent` desired state. The local player displays **No content assigned**; it never mislabels this configuration state as an invalid licence.

## 8. Device manifest semantics

An immutable manifest contains:

- schema/protocol version;
- tenant/device and desired-state identifiers;
- created/effective/schedule metadata;
- ordered items with immutable content version, byte size, SHA-256, media type, duration/playback parameters; and
- manifest digest/signature/binding metadata as selected in the licence protocol ADR.

The device rejects:

- unsupported schema/algorithm;
- wrong device/tenant/version binding;
- duplicate or unsafe paths;
- missing/duplicate ordering;
- unapproved media types or invalid limits;
- digest mismatch; and
- any manifest not covered by current authorization.

## 9. Local player API

The loopback-only player surface is intentionally narrow:

| Method and path | Purpose |
|---|---|
| `GET /player/v1/state` | Return `licensed`, `notLicensed`, `synchronizing`, or safe diagnostic state |
| `GET /player/v1/manifest` | Current locally authorized sanitized playlist |
| `GET /player/v1/content/{opaqueId}` | Stream only a content object in the current authorized manifest |
| `POST /player/v1/events` | Report allowlisted playback health events |
| `GET /player/v1/health` | Local service liveness for systemd/kiosk startup |

The local service rejects traversal, arbitrary paths, external origins, oversized events, and access to inactive/cached-but-unauthorized versions.

## 10. Contract verification

- Generated OpenAPI is linted and retained per release.
- Administration clients are generated or type-checked against the contract where practical.
- Device protocol golden files/test vectors cover canonical signed leases and manifests.
- Backward/forward compatibility is explicit for backend, agent, player, lease, and manifest versions.
- Real TLS integration tests prove certificate behavior; mocked headers are insufficient evidence.
- Every route receives authentication, authorization, tenant-boundary, validation, rate-limit, safe-error, and audit test coverage appropriate to its risk.
